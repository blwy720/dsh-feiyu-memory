# DSH 宿主接入与验证范围

本文对应 v0.6.0（2026-10-24）；宿主验收目标为 DSH 0.2.1-rc.2。Windows 和 Android 使用同一代码包。实际执行的版本、平台与结果记在 [验收记录](acceptance.md)，历史记录不代表新版已经完成同样验证。安装与数据恢复见 [安装与导入](安装与导入.md)。

## 宿主接口与范围

| 接口 | 实现边界 |
| --- | --- |
| 插件 | 无宿主 npm 运行时依赖；Standard Schema v1 Config，`apply` 返回 disposer。 |
| `session/event` | 仅收已提交 append、当前 live session 对象、`isOwnSeq` 的自有消息，保持原始 text 块边界。 |
| `AgentRegistry` | profile 模式通过 `roots()` 与 live 对象判定主会话；普通分叉不因 `parentSession` 自动排除。 |
| 子代理 | 检查 `header.origin`、`delegationDepth`、`subagentDepth`，即使恢复成 runtime root 也不能进入主会话共享范围。 |
| 工具 | 参数校验、调用 agent 所属验证与同一共享范围入口；原文管理员导入、正文释放及备份不注册模型工具。 |
| `system-prompt/assemble` | 按固定 section 名替换，地图、C、B3、首轮 A1 与每轮相关召回分区；有界 DATA 不能变成执行指令。 |
| 卸载 | 解除事件与工具注册，关闭 SQLite，停止可选备份检查；不保留额外模型任务。 |

`sessionScope: owner` 是兼容默认，要求 `ownerSessionId`；`profile` 共享当前配置中获准的实时主会话。缺少必要宿主接口时明确失败，不退化为所有会话都可访问。每个实例使用独立 `dataDir`、`instanceId`；profile 共享不能用来隔离需要相互保密的身份。

显式 `participation: interactive` 后，真人参与轮次进入 A1；`solitude` 不采集聊天正文，只记录 B 统计。B2 的冲浪关键发现由专属工具显式写入，不采集网页全文。采集 ID 包含实例、会话和消息归属；普通分叉继承的历史不重复采集。记忆工具及无法可靠分离的工具回声不重新变成原文证据。

同一宿主不应重复启用注册同名工具的插件行。其他记忆注入器是否保留应由使用者决定；本模块不扫描、迁移或卸载它们的数据。

`toolMode` 缺省为 `compatible`，注册全部 23 个业务工具，保持旧配置兼容。新安装模板选择 `compact`，初始注册 search、fetch、prepare、manage、review 五个业务入口及 `memory_tools` 发现入口。只有显式调用发现入口时才开启本插件白名单内的其他工具，不执行对应操作，不改动其他插件。开启状态在当前插件运行期间对授权主会话共享，重启回到配置初始集合。卸载解除自己持有的注册。

## 提示与维护

正常装配提示时检查审查队列及已获批准的到期维护，不创建额外 DSH 会话或后台提炼模型任务。默认本地召回无需额外模型；下文可选语义辅助只有显式配置后才发送 embeddings 请求。

- A1 提前审查与满 168 小时补审均由主模型处理；工具提交不直接删除。维护只让已审到期原文退出活动池，未审保留，引用或管理员保留的原文继续作为证据。
- A2 当前版本满 30×24 小时后进入审查队列；装配只执行有效、逐版本批准的退出活动池，不自动生成 A3，不释放未审正文。进一步正文释放由管理员显式 `purge-a2` 完成。
- B2 首次创建后 14×24 小时到期，修改不续期；到期默认隐藏，维护清理正文，仅留必要哈希与幂等记录。
- 提前审查提示不按词频决定重要性，也不保证模型会执行。模型中断或未继续运行时，队列保留。

醒来地图提供检索、阅读、审查与更正路线。`autoRecall:true` 默认按当前真人消息及有限上下文在本地查找相关记忆，独立 DATA 区默认最多 5 条、2400 字符；缺乏实质线索时可不返回。相关性优先于单纯新鲜度，不要求真人先说“我记得”。待办提示按变化／会话状态控制重复，审查进度通过 `memory_manage` 主动读取。候选是有来源性质的历史资料，不是把用户原话拼成新指令，也不表示模型已经核验完整内容。

C DATA 只承载符合注入条件的关系网。`fact`／`self_report` 可以无原文写入 C，但自动注入仍要求逐字可定位的来源及至少一个 `supports` 声明；否则只可查询，并计入待核查数量。有明确推理依据与不确定性的 `inference` 可按推断性质注入，已有引文仍须可核对，允许没有原文引文。两种路径均不等于事实验证。

B3 DATA 包含有效自身喜好／情感，以及当前 C 第一层人物明确表达的喜好，分别保留 `subject`。非自身须通过原文声明匹配及第一层范围检查。争议、待复核、撤回、失去当前范围资格的内容不作为有效资料注入；保留历史。`target` 不能取代持有者。C 与 B3 使用紧凑卡片，少量自身连续性资料与当前话题候选优先，完整证据按需读取；过长条目可只给定位信息，不能把删掉否定／条件后的半句当结论。

两个区都提供 `total`、`shown`、`omitted`，并区分 `awaitingVerification`、`selectionOmitted`、`budgetOmitted`；B3 另有 `scopeOmitted`。C 的 `counts` 分别计人物节点、关系边与各自显示数；总条数不是人数。缺少预算或不匹配当前话题不等于资料丢失，也不能把省略内容当作已读。

A3 固定 `derived_only`。v0.5.0 新写入只接受事实陈述／自述及时间、人物、事件正文；历史推断仍按历史性质读取。轻量来源时间和精确覆盖关系可以在父正文释放后保留，不因此声称原话仍可查。更正沿 A3 固有来源或 C/B3 显式依赖传播待复核；现状变化单独记录，不抹去历史。

D 的 `learned`／`tried`／`verified` 分别记录学到、尝试过、声明验证成功；尝试及验证需要方法、结果与原文证据，程序不会执行经验步骤或自动证明成功。事项线关联精确版本。轻量复核追加事件，不重写历史正文；到期和依赖变化应检查 `reviewDue`、`dependencyReviewPending`，保留的 `valid` 不代表当前保证。合并仅支持同 kind 的 A2 memory/doing，保留来源并可撤销，不合并 C 身份或 B3 持有者。

## 召回范围、可选网络与采集隐私

本地索引使用关键词、别名和有限错字匹配；原文引用仍要求逐字命中。模糊或语义候选不自动变成同一人物、矛盾、独立证据或已验证事实。`autoRecall:false` 仅关闭每轮相关召回，首轮 A1、C/B3 与显式记忆工具继续按原规则工作。

`semanticEndpoint` 与 `semanticModel` 同时配置时，启用兼容 embeddings 的语义辅助；可选 `semanticApiKeyEnv` 指定进程环境变量名，不将密钥写入记忆配置。最多 64 条当前精炼条目加词法候选，合计最多 80 条，并非全库向量检索。远程服务会收到脱敏截断后的查询与精炼候选文本，可能收费；A1 原文候选只留在本地检索。远程只允许 HTTPS，本机回环可 HTTP。默认超时 1500ms，`semanticTimeoutMs` 可设 100～5000ms；超时或服务失败使用本地结果，取消／卸载不继续应用迟到结果。

新 A1 在进入模块存储前过滤已知密钥、令牌、私钥及凭据模式；不追溯改写旧 A1、旧导出、旧备份或宿主自身的聊天日志。助手来源识别支持显式链与已读取资料中至少 20 字符的逐句原样复用，并保留派生片段；不能识别全部语义改写或所有秘密。`privacy-audit` 直接以 SQLite 只读连接统计现存权威文本，输出不含秘密正文，不通过构造 MemoryStore 触发迁移；备份和派生文件不在该扫描范围。

## 首轮 A1 的时序与完成证据

使用实际 Session 的 `eventAt`、`seq`、`inheritedEventCount` 识别第一个自有轮次。真人参与由 `agent/inbox/claimed` 的消息来源判断，因为目标宿主先装配提示，再提交 `user/message`；插件启动后的第一条事件不等于会话首轮。

新主会话首轮从其他主会话中选择最近正常完成的一轮 A1。只有 `turn/end reason.kind=completed` 且完整用户／普通助手文本可核对的轮次入选；中断、失败、子代理、独处、工具结果和缺失文本不入选。原始块保留角色、时间、session、turn、ID 与读取指针，附件遗漏如实标注。

首轮选择持久化为某个来源或明确空结果；重试、同轮多次装配和重启不换来源，第二轮移除。已选来源过期或退出 A1 后，不从保留证据区重新注入，也不静默替换其他轮。字面截断带明确标记，不改写成模型摘要。`recentTurnMaxChars` 默认 8000、范围 1024～32000；字符预算不是 tokenizer 测得的 token 保证。

旧日志补核只处理有界的现存 A1 候选，最多 32 组。通过可选 `sessionQuery` 只读核对完成事件、主会话身份及全部相关原文哈希；无接口、缺失记录或文本不匹配就跳过。真实 Cordis 的可选服务用 `ctx.get('sessionQuery')` 获取，避免未声明强依赖时直接访问被拒绝。

历史查询按会话分组，一次只保留一个完整日志，等待总预算为 2000ms。首轮取消或插件关闭会停止等待；底层 `readSession` 没有取消接口，迟到结果／错误会被消费，但不再改变已固定的选择。同步解析与验证仍取决于单个日志规模，不能把它当作对任意巨型日志的硬实时保证。实时完成的轮次直接建立元数据索引，不依赖额外模型调用。

## 自动备份生命周期

v0.5.1 客户端通过宿主 ModuleLoader 与 `settings.section` 插槽提供“肥鱼记忆备份”。复用宿主 React 与主题，无新增运行时依赖。管理接口通过 `connection.fetch.register` 注册，使用宿主认证、Origin/Host 检查和 owner 权限，不另开端口；缺少可选界面服务时，原有记忆采集与 CLI 仍可使用。

宿主始终创建备份管理器；界面保存的 `backup-settings.json` 优先于初始四个备份配置项，保存后立即生效。配置损坏会阻止自动执行，明确报错，重新保存有效设置后恢复。管理器串行执行手工操作与自动检查，卸载时等待已开始的操作并清理路由及上传暂存文件。

`backupEnabled` 默认关闭。开启后，宿主启动和运行中的约一分钟检查仅判断计划是否到期、数据库是否变化；无需模型参与。应用关闭时不执行，卸载停止计时与检查。失败记录到备份状态，不阻止主对话与记忆提交。

每个配置只有一个外部备份目录；按 1～30 天或自然月维护单个 `latest.feiyu-backup`。验证新包成功才替换；验证或替换前失败不会覆盖旧包。替换后同步或状态写入失败可能导致操作未确认完成，目标可能已经更新，应检查并验证文件。不自动保留历史版本。手工导出必须另取名称。导入保留身份且只接受新／空目录；正常启动才对恢复库迁移与维护。资源上限和实际 CLI 见安装文档。

## 本地隔离验证

```powershell
npm test
npm run check

# 可选真实程序集成：将公开示例路径替换为自己的只读程序代码副本。
# 代码副本不能包含用户记忆、凭据或聊天日志，也不随插件发布。
$env:FEIYU_DSH_MODULES_ROOT = 'C:/RuntimeCopies/dsh/node_modules/@deepseek-ai'
$env:FEIYU_PREVIOUS_PACKAGE = 'C:/RuntimeCopies/previous-feiyu-memory'
npm test
```

未指定相应环境变量时，真实宿主或实际旧包升级用例可能跳过；平台专属测试也按环境决定是否运行。真实程序集成使用临时 SessionStore、AgentRegistry、SystemPrompt 与 ToolRuntime，不连接活动用户会话、不发送模型消息。模拟宿主、真实程序隔离集成、手机实机部署和模型长期语义质量是不同层次，须分别报告。

本版 schema 7、字典 v6。升级前保留旧代码、设备配置及已验证的一致性数据快照，停止旧写入再更新。回退必须用升级前兼容快照恢复到新目录，旧代码不得直接打开已升级的新库。SQLite 为权威数据，文件投影故障可用 `projectionPending` 与 `rebuild` 恢复。已经 `committed` 的写入不应因投影失败重新制造版本。
