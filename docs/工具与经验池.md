# v0.6：读取、整理、事项线与 D 经验池

本页介绍肥鱼怎样调用记忆工具，以及你可以怎样提出要求。代码块中的 ID、网址、内容均为公开合成示例；实际调用必须使用自己库里已读取的 ID、版本和原文，不能把示例当成证据。工具调用由肥鱼执行，不是终端命令。

Windows 和 Android 使用同一套接口。每个记忆实例有自己的身份和数据，主会话共享范围按插件配置决定，子代理不混入；电脑与手机不会因升级自动同步记忆。

安装、升级、导入导出与回退请看[安装与导入](安装与导入.md)。

## 两种工具显示模式

`toolMode` 只控制哪些工具一开始出现在模型的工具列表中，不删除已有数据或工具实现。

| 模式 | 行为 |
| --- | --- |
| `compatible` | 兼容模式，启动时注册全部 23 个记忆工具。旧配置省略该字段时使用此模式。 |
| `compact` | 精简模式，启动时只注册 5 个业务入口和 1 个发现入口；其他工具按需开启。新安装模板采用此模式。 |

精简模式初始工具：

- `memory_search`：找线索，可按池、主体和时间筛选。
- `memory_fetch`：简洁批读或读取同一轮对话。
- `memory_prepare`：写入前定位原文、找相关旧记忆和区分同名人物。
- `memory_manage`：D 经验、复核、事项线、合并及进度日报。
- `memory_review`：A1 提纯审查、独立批次或审查历史。
- `memory_tools`：查看工具目录、按需开启其他记忆工具。

例如肥鱼需要维护喜好和关系网，可先调用：

```json
{"names":["memory_preference","memory_core_write","memory_graph"]}
```

这是 `memory_tools` 的参数。空对象 `{}` 返回简短目录。开启动作只注册工具，不执行喜好写入、关系修改或其他操作。它只接受本插件的工具白名单，不改变其他插件；重复开启无副作用。

开启结果在本次插件运行期间对所有获准主会话有效，重启后回到配置的初始集合。没有“全部重置”操作，以免一个会话影响另一个会话正在使用的工具。

要修改模式，仅在本插件已有配置对象中增加 `"toolMode":"compact"` 或 `"toolMode":"compatible"`，不要用这一行替换整个 DSH profile。配置变更后按宿主方式重载插件或重启 DSH。开发者通过 `createTools(store)` 调用时仍可使用完整工具 API。

## 简洁阅读和批量阅读

你可以说：“把这几条一起读给你自己看，只取正文、说话者和时间，必要时再看出处。”

`memory_fetch` 默认返回简洁正文，并保留 ID、精确版本、角色、时间和必要的证据/有效性状态：

```json
{
  "ids":[{"id":"example-raw","kind":"raw"},{"id":"example-memory","version":2}],
  "budget":8000
}
```

- 一次支持 1～50 个定位对象。一个 ID 不存在或读取失败，不妨碍其他 ID 返回。
- `budget` 是整个呈现后 JSON 响应的字符上限，范围 800～48000，默认 8000；不是 token 数。
- `hasMore:true` 表示尚未读完，用返回的 `cursor` 继续，续读时只传 `cursor` 和可选 `budget`。
- 游标固定首次读取时的条目版本，不会在另一会话修改后悄悄换成新版本。游标保留一小时，插件重启会失效；失效后重新发起读取。
- 游标依赖当前工具实例，不能跨独立 CLI 进程复用。CLI 长正文续读请使用 `read --id ... --version-number ... --offset ... --limit ...`；已返回的精确版本不可省略。
- 原文很长时会分段，`textPage` 标记精确位置及截断。不能把第一页当作完整内容。
- 可选 `fields:["text","role","recordedAt"]` 进一步选择字段；ID/版本等定位信息仍保留。未请求的正文不强迫续读。
- 若请求 `currentValidity`，同时保留复核时间、到期及依赖待复核警告，避免只读到一个脱离上下文的 `valid`。

需要核验时，可以按需开启 `memory_read` 并使用 `view`：

| `view` | 内容 |
| --- | --- |
| `body` | 简洁正文和必要状态。 |
| `evidence` | 引文、逐字定位、来源、支持声明及外部链接。 |
| `history` | 版本、关联更正、复核和合并状态，可分页。 |
| `full` 或省略 | 保持旧版完整读取方式，兼容已有调用。 |

## 按整轮查看经过

已知一条原文 ID 时，可以用 `memory_fetch({"anchorId":"example-raw"})` 定位它所属的轮次；也可同时提供 `sessionId` 和 `turnId`。

只有相同 session 和 turn 的原文才会归为一轮，不根据内容相似或时间靠近拼接。已有正常完成索引时使用索引顺序，否则按记录时间及原始采集顺序排列。输出会标明顺序来源。

这里返回的是仍可读取的该轮原文；退出保留范围、已清理或没有采集到的内容不会被补写。它不改变“新会话首轮只预注入一次最近完成的一轮 A1 原文”的规则。

## 写前检查和同名人物

你可以说：“这次已经实际启动成功，先看看旧记忆里有没有相反记录，再更新。”

肥鱼可以先调用 `memory_prepare`，提供准备保存的 `text`、已读原文 `rawIds` 和可选目标 `pool`：

```json
{"text":"我今天实际启动成功了","rawIds":["example-confirmation"],"pool":"a2"}
```

当文字确实逐字出现在原文时，工具返回可用的原文 ID、引文和位置；否则返回定位线索，请先读原文。标点或 Markdown 不一致不能靠模糊匹配自动通过证据检查。

相关旧记忆是“需要比较”的候选，不是系统已经判定的矛盾。新的状态可能只是后来改变，不能自动否定过去。

同名人物可用 `memory_prepare({"entity":"姐姐"})` 查询。若有多个候选，会列出不同实体 ID 和区分信息。关系称谓、别名和身份是不同信息：同样叫“姐姐”不会自动合并为一个人，写关系仍须选准确实体 ID。

`memory_search` 可显式加 `"fuzzy":true`，对英文工具名等少量字符错误补充最多 20 个候选。近似命中不会放宽既有池、日期等过滤，也不会自动证明人物身份或事实。

## 批量提纯：独立单元可部分成功

你可以说：“把这批原文分成相互独立的小组整理，有错误就留下那一组，别让其他组全部重来。”

`memory_review` 增加 `action:"batch"`。每项有稳定唯一的 `key`、原文 `rawIds`、提纯 `entries` 或明确不提炼的 `omissions`，以及 `reason`。外层提供唯一 `requestId`：

```json
{
  "action":"batch",
  "requestId":"example-review-batch",
  "items":[
    {
      "key":"small-talk",
      "rawIds":["example-greeting"],
      "entries":[],
      "omissions":[{"rawId":"example-greeting","reason":"仅问候，没有新的长期信息"}],
      "reason":"已读原文，明确略过无新增内容"
    }
  ]
}
```

独立单元分别提交和返回结果，失败的原文继续待审；成功单元不会因另一个单元失败而撤销。重试保持外层 `requestId` 和各项 `key`，已成功项相同输入不会再次写入。

共享原文、相互依赖的实体和关系，必须放在同一单元内，继续保持原子提交。这能避免只保存了一半内容，就把另一半需要的原文标成“已审完”。

审查队列使用返回的 `nextCursor` 继续。旧 `offset` 接口保留兼容，但处理前页后不要再用旧位移继续翻页。新导入的较早原文会进入新的审查轮次，不能被错误计作已经审完。

## D 池：学到的方法和经验

D 保存“用途、适用条件、关键方法或结论、验证情况”，不会仅凭一句“我学会了”就认定实际成功。避坑信息和失败条件可写在 `method` 中。

| 状态 | 含义与要求 |
| --- | --- |
| `learned` | 从资料或已有记忆中学到，尚未实际尝试；必须保留来源，不附成功验证声明。 |
| `tried` | 已尝试，需写验证方式、实际结果和对应原文依据；结果可以是失败。 |
| `verified` | 记录者声明已验证成功，必须附方法、结果和原文依据，不能仅用旧回忆的重复转述作验证。系统仍标明 `autoVerified:false`。 |

使用 `memory_manage` 的 `knowledge` 操作，例如：

```json
{
  "action":"knowledge",
  "requestId":"example-learning-1",
  "reason":"读到启动说明，尚未运行",
  "knowledge":{
    "id":"example-comfyui-start",
    "expectedVersion":0,
    "purpose":"启动 ComfyUI 并判断是否运行",
    "conditions":["本机已经安装所需依赖"],
    "method":"检查启动日志和进程，再核对本机页面是否可访问。连接失败时先记录错误，不直接宣称安装失败。",
    "validationStatus":"learned",
    "externalSources":[{"url":"https://example.com/comfyui-guide","title":"合成示例资料"}],
    "environment":{"name":"Windows","version":"11"},
    "hooks":["ComfyUI","启动失败"]
  }
}
```

修改已有经验时提供当前 `expectedVersion`，生成新版本，不覆盖历史。升级到 `tried` 或 `verified` 还需提供 `validation:{method,result,checkedAt?,sources}`；其中 `sources` 必须定位到真实原文。

`sources` 是 A1 原文引文；`externalSources` 是外部资料链接；`dependencyEntries` 是已有记忆的精确版本。三者不互相冒充，也不会因为多次摘要增加独立证据。

电脑验证成功的方法不自动适用于 Android。用 `environment` 和 `conditions` 记录设备、系统、软件版本及限制。读取方法不等于自动执行里面的步骤。

D 可通过 `memory_search({"pool":"d","q":"ComfyUI"})` 查找，再用 `memory_fetch` 或 `memory_read` 展开。任务完成或发现可复用方法后，由运行中的肥鱼进行判断和保存；插件不会在应用关闭时自行调用模型整理。

## 事项线、复核、合并与撤销

这些操作都使用 `memory_manage`，写操作必须有 `requestId` 和 `reason`。

| `action` | 参数块与用途 |
| --- | --- |
| `link_thread` | `thread:{threadId,title?,entries:[{id,version}]}`，串联跨会话的同一事项。新事项需要标题。 |
| `read_thread` | `thread:{threadId,limit?,cursor?}`，读取事项关联的精确版本，必要时批量展开正文。 |
| `revalidate` | `check:{targets,currentValidity,check,sources,checkedAt?,reviewAfter?}`，追加当前有效性的复核事件。 |
| `merge` | `merge:{targets,entry}`，把同类型的当前 A2 memory/doing 条目合并为新 ID，保留每份来源。 |
| `revoke_merge` | `merge:{mergeRequestId}`，撤销指定合并；恢复源条目正常展示，合并产物保留历史并标归档。 |

事项 `threadId` 与聊天 `sessionId` 不同。一条事项可以跨会话，一个会话也可以讨论多条事项。

复核 `currentValidity` 可为 `unknown`、`valid` 或 `invalid`。确认有效或无效时，必须有原文依据和 `check:{method,result,actor?}`；系统记录“谁怎样确认”，不会把逐字引用命中升级成自动事实验证。`reviewAfter` 到期只设置 `reviewDue`，需要再查，不直接删掉记忆，也不把过去的内容判错。

还要检查 `dependencyReviewPending` 和 `dependencyReviewReasons`：当明确依赖的来源后来失效、到期待审或合并被撤销时，派生内容会提示再核对。它可能仍保留原来的 `currentValidity:valid`，那是上次复核记录，不能只取这一项当作当前保证。读取、检索和写前候选都会带必要的关联状态。

合并目前限于同类型 A2 记忆或事项，不合并 C 人物身份、C 关系或 B3 喜好持有者。合并产物必须保留准确的父版本与全部原始引用；旧条目仍可查。跨来源内容是否真的能合并，需要肥鱼判断。

读结果和候选中的 `threadIds` 可继续打开相关事项线。合并产物仅继承已存在的父版本事项关联，不根据文字猜测新关联；默认当前检索避免把已合并的来源与产物重复排在一起，明确查历史仍可追溯。

## 查看进度和每日记录

你可以说：“告诉我整理到了哪里，最早还有哪段没审，今天真正写入了什么。”

- `memory_manage({"action":"progress"})` 返回已审数量、到期待审数、最早未审原文及连续覆盖边界。
- 连续覆盖边界表示该时间**之前**的已知 A1 原文都已处理，不是“最新一条审过的日期”。迟到导入可能让边界回退。
- `memory_manage({"action":"report","date":"2026-10-24"})` 查看按记忆库时区统计的日报，可用 `limit` 和 `cursor` 分页。
- 日报区分新增、更新、更正、撤销和已审原文，基于实际提交记录；失败和相同请求重放不算新的成功。历史覆盖起点会明确说明，旧版本没有记录的动作不会编造补齐。
- 运行期间成功写入会更新 `logs/daily/YYYY-MM-DD.json`。它是本地记录，不会自动向别人发送消息；无活动时不制造空日报。

## 使用时仍需保留的区别

- “记录了某人说过什么”不等于“话中主张已证实”。
- “找到相似记忆”不等于“确定是同一个人或同一件事”。
- “过去有效”不等于“现在仍有效”；到复核期也不等于保留期到期。
- “肥鱼复述了旧记忆”不构成一份新的独立证据。
- “没有检索到”不等于“从未发生”；可以明确扩大时间、主体或关键词范围后再查。
