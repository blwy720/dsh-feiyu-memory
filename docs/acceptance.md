## 覆盖的关键场景

| 范围 | 已验证行为 |
| --- | --- |
| CLI 全流程 | 初始化→原文采集→检索→读取→审核→滑动→保留原文再次读取 |
| 原文与版本 | 重启后内容一致、重复采集不重复计数、不同内容复用 ID 被拒绝、旧版本不覆盖、按时间可发现旧版本 |
| 条件句反例 | “如果中了800万”可逐字定位，但不会自动确认为实际中奖或当前事实 |
| 来源防腐 | 摘要不能作为 raw 证据；同源不自动算独立；助手原文只证明助手说过什么 |
| 记忆回声 | 自身记忆工具结果、可混合记忆输出的 run_code 结果和无法关联调用的工具结果不再成为新原文证据 |
| 双时间轴 | 去年发生、今年记录，以及本地午夜边界分别可查 |
| 检索 | 中文原文兜底、显式别名、情绪仅辅助排序、候选长度与分页可复现 |
| 隔离 | 错误实例／时区拒绝打开；陌生或伪造宿主会话不能取回记忆；目录穿越与符号链接拒绝 |
| 独处 | 不保存正文、会话信息或精确消息时间；最小去重凭据可跨重启重复处理 |
| 淘汰 | 按自然日保留七天；未审核不删；已引用原文保留；同一天部分删除不残留旧摘要摘录 |
| 中断恢复 | 实际子进程在写临时文件后退出；重开清理遗留原文；损坏投影清单可重建 |
| 醒来条 | 每次 assemble 都提供且不重复累加；只使用固定查询入口，任意事项 ID 和正文均不能进入常驻提示 |
| 宿主采集 | 已提交消息、真实延迟回答、实际事件顺序、继承／替换消息隔离、文本块边界、跨重启消息级池分类、附件遗漏提示 |
| 权限边界 | 模型不能调用原文导入或删除审核；管理员 CLI 才提供相关入口 |
| 删除约束 | 直接 DELETE／REPLACE 被拒绝；合法滑窗审核、保留原文、删除记录同事务；审计未引用的原文缺口 |
| Windows 文件占用 | 真实 FileShare.Read 锁下 CLI 退出 0、committed/pending 明确；锁期间新进程可继续采集；解锁重建恢复；doing 无须重试产生额外版本 |
| 限量读取 | 正文分页可原样拼回；证据分页去重；大型引文和元数据不会导致一次展开几十 MB |
| Markdown 重建 | 删除日索引和醒来条后 rebuild 恢复；已删除日重建不重新出现原文，重开仍可保留空正文统计 |
| 审计状态 | 当前事项／实体投影和检索索引体现审计降级；历史版本保持原写入记录 |
| 旧版升级 | 用真实安装的 0.1.0 创建合成库；0.1.1 事务迁移到 schema 2，活动原文、保留证据、旧版本均保留；旧版拒绝再次打开迁移后的库 |

另对当前真实 DSH SessionStore 使用 Windows 共享锁：宿主继续运行，B 计数从 1 增为 2，`captureFailed:false`、`projectionPending:true`。这里验证的是受控文件占用后的行为，不是对系统随机 EPERM 发生频率的测量。

旧库在 v0.1.0 下已经删除的原文没有新版删除记录；迁移不会凭空补造授权证明。审计可能报告这些历史缺口，需要结合旧审核记录判断；不能将其直接断言为恶意删除。

## 仍待实际验收

1. 在目标 DSH 配置启用后的真实对话，以及同版本手机的运行环境兼容性。PC 与手机版本均为 `0.2.0-rc.2`；当前桌面库的隔离实例测试已通过，尚未在手机设备上运行。
2. 设计稿要求的连续两周使用、漏触发率、中文长对话检索质量、无依据陈述率与人工抽查。
3. 自动语义提纯、自动归档／衰减／复活、向量检索、二进制附件和灵枢 API 迁移均不属于本次 v0.1。
4. 醒来条采用统计与指针，280 字符限制并非 tokenizer 测量的 token 保证。
5. 当前存储是明文。实例 ID／会话归属校验不等于操作系统访问隔离，逻辑删除也不等于介质安全擦除。
6. SQLite 事务维护权威数据；同一数据目录建议只由一个宿主进程使用。跨进程投影刷新不提供严格同步视图，后台服务同时运行时不应另启管理员修改流程。
