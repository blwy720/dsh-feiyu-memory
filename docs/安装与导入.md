# 安装、导出与恢复

本文中的路径、身份与文件名都是公开示例，需要替换为自己的配置。命令在插件代码目录内的终端运行，要求 Node.js 24+，不是发给肥鱼的聊天文字。

## 安装程序与导入数据是两件事

| 操作 | 输入 | 结果 |
| --- | --- | --- |
| 安装或升级插件 | `dsh-feiyu-memory` 代码目录或打包的 `.tgz` | 安装程序及默认禁用的配置行，不带个人记忆。 |
| 新建记忆 | 新的绝对 `dataDir` 与唯一 `instanceId` | 初始化一份独立记忆。 |
| 导入／恢复记忆 | `.feiyu-backup` 文件与新建或空目录 | 恢复原库的身份、时间、内容及版本，不与其他库合并。 |

Windows 与 Android 使用同一插件代码。正常分别使用时，每台设备使用不同的 `dataDir` 和 `instanceId`；同一 profile 的主会话共享，不等于跨设备共享。这里没有云同步或自动合并功能。

## 在 DSH 安装

当前验收目标 DSH 0.2.1-rc.2 的插件管理器提供侧栏“插件”和“添加插件”；该宿主支持输入本地插件目录或安装包的绝对路径。使用当前宿主的插件管理器完成安装，按其反馈处理依赖和配置。不同发行版本的入口以该版本为准。

安装包发布入口为 [最新 Release](https://github.com/blwy720/dsh-feiyu-memory/releases/latest)，代码位于 [项目仓库](https://github.com/blwy720/dsh-feiyu-memory)。下载后核对发布页提供的版本和校验值；代码仓库压缩包与记忆 `.feiyu-backup` 不是同一种文件。

本模块的安装补丁默认禁用插件，`dataDir`、`instanceId` 为空。先用当前宿主支持的配置方式填写本插件行，再启用。模块没有自行实现“导入记忆”或“导出记忆”的 GUI 按钮；本文恢复流程使用 CLI。

下面仅是插件行的配置对象，不能覆盖整个 profile 文件：

```json
{
  "dataDir": "C:/FeiyuData/desktop",
  "instanceId": "feiyu-desktop",
  "timezone": "Asia/Shanghai",
  "sessionScope": "profile",
  "participation": "interactive",
  "backupEnabled": false
}
```

- `dataDir` 必须是当前宿主进程可读写的专属绝对目录；实例与时区会绑定到它。
- `profile` 共享当前配置下的获准主会话，不共享子代理。省略时的兼容模式 `owner` 还要求 `ownerSessionId`。
- `interactive` 才保存真人参与轮次的 A1；安装补丁默认的 `solitude` 不保存聊天正文。
- Android 应填写其宿主实际可访问的绝对目录，使用独立身份，例如 `feiyu-android`。没有适用于所有 Android 启动器的固定路径，Termux 的目录也不等于另一个应用可访问的目录。

不要用另一个全局 CLI 的 profile 去替代桌面宿主自身的配置管理。也不要重复启用两个注册同名记忆工具的插件行。

`doctor --data ... --instance ...` 会打开并可能初始化、迁移该记忆库，并非只读检查任意陌生库的命令。检查备份应使用下文的 `verify-backup`。

## 手工导出一个独立备份

备份相关命令的目录和文件参数必须使用**绝对路径**。导出目的文件应在记忆目录之外，文件名不能是自动备份保留的 `latest.feiyu-backup`，也不能覆盖已有文件。

Windows PowerShell 示例：

```powershell
node scripts/cli.js export --data "C:/FeiyuData/desktop" --instance feiyu-desktop --file "E:/FeiyuExports/desktop-before-upgrade.feiyu-backup"
node scripts/cli.js verify-backup --file "E:/FeiyuExports/desktop-before-upgrade.feiyu-backup" --instance feiyu-desktop
```

Android 若有可运行 Node.js 24+ 的终端，可使用相同 CLI。以下为 POSIX shell 模板，先把路径改成该进程实际能访问的绝对路径：

```sh
MEMORY_DIR="/absolute/path/to/android-memory"
EXPORT_FILE="/absolute/path/to/exports/android-before-upgrade.feiyu-backup"
node scripts/cli.js export --data "$MEMORY_DIR" --instance feiyu-android --file "$EXPORT_FILE"
node scripts/cli.js verify-backup --file "$EXPORT_FILE" --instance feiyu-android
```

导出使用 SQLite 一致性备份接口，不以只复制主数据库文件的方式遗漏 WAL 中的已提交写入。它不通过打开源 MemoryStore 来执行迁移或到期清理。手工导出不会改写自动备份的 `latest`；需要再导出时另取文件名。

备份是压缩容器，**不加密**。当前限制是解压后的单个 SQLite 数据库不超过 **64 GiB**，不是“压缩文件可达 64 GiB”的承诺。数据库上限不保证设备有能力验证同等大小的库。

验证除压缩结构、哈希、SQLite 完整性及外键外，还检查对应 schema 的权威表、必要列和 JSON 形状，并在一次性副本上执行当前 MemoryStore 的启动／读取检查。实际发布的导出／恢复数据库保持快照字节，不在此步骤迁移或清理；副本验证不会改写原库。

导出与验证需要额外临时磁盘空间，涉及多个数据库副本和派生文件；验证现有 MemoryStore 时也会消耗内存。工作线程设置了 V8 堆预算，超限可报告 `BACKUP_MEMORY_LIMIT`，这是安全失败，不是成功备份，也不是进程总 RSS 的硬上限。不要按压缩包大小估算所需空间。路径组件中的符号链接／目录联接不受支持。

`verify-backup` 不需要 `--data`。可选的 `--instance` 是预期身份校验，不会给包改名或更换身份。查看返回的 `manifest`、身份、时区、schema 和快照时间，确认它是准备恢复的那份库。

## 恢复到新目录

先验证，再导入。目标目录必须不存在或为空；命令拒绝合并、覆盖非空记忆目录，也不能直接恢复到磁盘根目录。

```powershell
node scripts/cli.js verify-backup --file "E:/FeiyuExports/desktop-before-upgrade.feiyu-backup" --instance feiyu-desktop
node scripts/cli.js import --file "E:/FeiyuExports/desktop-before-upgrade.feiyu-backup" --target "C:/FeiyuData/desktop-restored" --instance feiyu-desktop
```

`restore` 是 `import` 的同义命令。两者使用 `--target`，不需要 `--data`。`--instance` 可省略，此时仍保留包内身份，不会生成新身份。

1. 停止将要切换的旧记忆写入方，保留旧目录；不要一边恢复一边让另一个进程写入目标。
2. 验证包的完整性、身份和时间，导入新目录。
3. 将插件 `dataDir` 改为目标目录，`instanceId`、`timezone` 按恢复的 `identity` 配置。
4. 正常启动插件。它会迁移支持的旧 schema、重建 JSON／Markdown／索引投影，并按原始时间执行当前维护规则。
5. 检查启动结果与几条已知记录，再决定是否继续保留旧工作目录。不要把路径切换误当成自动同步。

需要单独重建时，在其他写入方停止的情况下执行：

```powershell
node scripts/cli.js rebuild --data "C:/FeiyuData/desktop-restored" --instance feiyu-desktop --timezone Asia/Shanghai
```

导入返回 `needsRebuild: true`、`projectionPending: true` 是等待正常启动重建的提示，不表示需要再次导入。

**恢复只回到快照所代表的状态。** 快照之后的新增、更正、撤回或删除不在包内；恢复较旧快照可能重新带回后来已删除的内容，不会与当前库自动对账。原始时间和保留期不重置；例如已经过期的 B2 不会因导入而重新获得十四天有效期。快照中已有的墓碑、退休与审查记录仍随库恢复。

跨设备迁移也保留原身份。不要把“将桌面备份恢复到手机”默认理解为“自动变成独立手机身份”，更不要把两份不同设备的库混入同一目录。若保留两份恢复副本同时使用，它们会各自演进，本模块不合并分歧。

备份只含本模块记忆库及恢复所需身份信息，不恢复 DSH 聊天列表、原宿主会话文件、图片／音频附件、模型密钥或整个 profile。

## 可选自动备份

默认 `backupEnabled: false`。启用时给出位于记忆目录之外的绝对 `backupDir`：

```json
{
  "backupEnabled": true,
  "backupDir": "E:/FeiyuBackups/desktop",
  "backupSchedule": "interval",
  "backupIntervalDays": 1
}
```

| 配置 | 实际含义 |
| --- | --- |
| `backupSchedule: interval` | 自上次成功起每 1～30 个 24 小时检查到期；`backupIntervalDays` 默认 1。 |
| `backupSchedule: monthly` | 按配置时区，从上次成功时间推进一个自然月；目标月没有该日时收敛到月末。不是固定 30 天。 |
| `backupEnabled: false` | 不启用宿主自动备份任务。 |

自然月模式省略 `backupIntervalDays`，或保持默认 1；不要同时设置其他间隔天数。自然月从上次实际成功日期计算，并不保证永久固定在最初的某个月末日。

启用后宿主启动时及运行中的约一分钟间隔检查是否到期且有变化，首次或目标缺失时可补做。应用关闭时不会执行。没有变化时检查不一定生成新文件；失败会记录状态并在后续检查重试。此任务不调用模型。

自动备份只保留一个 `latest.feiyu-backup`。新快照生成、验证成功后才替换旧文件，失败保留旧的有效备份；**没有自动多版本历史保留**。同一个目标目录不能混用不同身份的备份。若现有目标损坏或身份不符，会报告错误，不盲目覆盖。

可将目的目录放在另一个物理磁盘，以降低单盘故障同时损坏原库与备份的风险；也允许其他合适目录。程序不判断两个盘符是否实际属于同一物理盘。当前每个插件配置只设一个自动目标，额外磁盘可另做独立命名的手工导出。

查看状态不会打开数据库：

```powershell
node scripts/cli.js backup-status --data "C:/FeiyuData/desktop" --backup-dir "E:/FeiyuBackups/desktop"
```

手工运行一次**按计划检查**，不强制提前备份，也不安装后台定时器：

```powershell
node scripts/cli.js backup-check --data "C:/FeiyuData/desktop" --instance feiyu-desktop --backup-dir "E:/FeiyuBackups/desktop" --interval-days 7
```

或自然月计划：

```powershell
node scripts/cli.js backup-check --data "C:/FeiyuData/desktop" --instance feiyu-desktop --backup-dir "E:/FeiyuBackups/desktop" --schedule monthly --timezone Asia/Shanghai
```

核对 `lastSuccessAt` 与 `lastError`，不能仅凭曾经成功就认定最近更改已保护。磁盘离线、空间不足或验证失败时，聊天与记忆主流程不应因备份失败停止；但旧备份也不会自动包含新写入。

## 升级、分享与排错

升级前使用独立名称手工导出并验证，保留旧代码；停止写入后更新插件，再让新版正常启动迁移。当前 schema 为 6，旧程序可能拒绝打开新版库。若需要回退，使用与旧代码兼容的备份恢复到新目录；不要只替换代码后强行打开已升级数据库。

公开分享程序包时，只分享代码、文档与合成样例，不放入真实 `dataDir`、`.feiyu-backup`、聊天日志、宿主配置或个人凭据。许可证保持 `UNLICENSED`；“可本地安装”不等于授予新的开源许可。

| 现象 | 处理 |
| --- | --- |
| 导入提示目录非空 | 换新目录，先保留已有数据；不能用导入覆盖现有库。 |
| 身份或时区不匹配 | 核对备份 `identity` 和配置；不要为了绕过校验直接编辑身份文件。 |
| 导出文件已存在或使用 `latest` 名称 | 为手工导出取一个新的独立名称。 |
| 校验失败或 `BACKUP_MEMORY_LIMIT` | 保留源库与旧有效备份；检查错误、可用磁盘与内存。不能把未验证成功的包当成可恢复备份。 |
| 提交成功但 `projectionPending: true` | 先解决文件占用／权限问题，再正常启动或 `rebuild`；不要重复创建记忆版本。 |
| 导入后与最新库不一致 | 对照快照时间；恢复不会自动补上快照后的新增、更正和删除。 |
